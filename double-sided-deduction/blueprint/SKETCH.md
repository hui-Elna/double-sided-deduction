## 1. 定位

做什么：用户随口说个想法/说得简单或没讲清楚时，在内部用两个视角辩论 2-3 轮（建设者做扎实→挑剔者找漏洞抬标准→收敛），对外只交付严谨全面的方案、不展示辩论；何时用：用户有个想法想变成靠谱方案、说得模糊、想挑毛病想周全（含大白话：我有个想法帮我完善下/帮我把这事做成方案/帮我想周全点/这方案有没有坑/帮我挑挑毛病/你帮我多想想/我说不清楚你帮我理理/帮我参谋参谋/内部推演一轮/双面推演）；何时不用：纯闲聊无想法、要展示完整辩论、需实时数据或专业资质判断；定位=通用方案严谨化工具，投资/量化仅是用户的一个用例而非 skill 边界（用户 2026-11-22 修正）；语言：中文主语言。目录名 adversarial-convergence 沿用为内部标识

## 2. 用户与场景

- **用户**：任何向 AI 提设计想法、但说得简单或没讲清楚的人（尤其是不熟悉如何提要求的生疏用户），覆盖产品设计 / 商业战略 / 日常方案推敲
- **场景**：目前在 workbuddy 上靠手动或通用对话能力完成「AI 直接给出的方案未经对抗性检验」，每次都要重新描述一遍要求，AI 直接给出的方案未经对抗性检验，用户拿到手才发现漏洞；想让 AI 内部扮演建设者与挑剔者做一轮攻防推演，但不要把辩论过程展示出来，只要收敛后的最终结论。
- **不做的事**：① 不展示辩论对话过程（仅显式要求时附 ≤5 行推演摘要）；② 不做纯闲聊、无明确方案主题的请求；③ 不做需实时数据或专业资质判断（法务/医疗/财务审计）的事；④ 不引入 scripts/ 与 references/、不做外部调用与文件产出（装不下再扩容）

## 3. 设计模式

采用 Pipeline × A 流程配方

依据：命中 Q1 信号：多步骤带 checkpoint；最在意「对抗过程内部化、不外显；输出单一口径的收敛结论；结论必须扛得住成本/效率/周期/风险/竞品等挑剔性质疑」，与该模式的强项一致；流程性质为「输入方案或命题 → 内部静默多角色攻防（建设者出方案、挑剔者提尖锐质疑并抬高目标）→ 内部收敛为兼顾双方核心诉求的结论 → 只输出最终结论；可选极简摘要层」

## 4. 输入 / 输出契约

- **输入**：用户必须提供 一个想法/方向/待落地成方案的念头（可以只说一两句、模糊、逻辑不清——这是常态，不是缺陷）；Agent 可主动读取 无（单文件无外部依赖）；缺失即不能开始 连主题都无法判断（完全不知道要做什么，才追问一次）；可默认 输出语言=中文、内部辩论轮数=2-3；必须确认 无——细节模糊时用合理假设补全，不打断用户，仅在方案里点明关键假设
- **输出**：最终交付物 一份单一口径的严谨全面方案（可执行方案 / 带条件折中判据，点明关键假设）；格式 对话内 Markdown（默认无角色标识、无辩论过程）；可选 用户明确要求时附 ≤5 行"推演摘要"；落盘路径 无；是否需报告·日志 否（对话即记录）
- **方法**：LLM 推理（内部静默多角色多轮辩论 + 收敛，无脚本、无外部依赖） ——决定 B06 决策 2
- **边界**：不属于本 skill 需实时数据、专业资质（法务/医疗/财务审计）、要展示完整辩论的任务；必须暂停并询问 连主题都无法判断时（追问一次）；应交由其他 skill 或工具 实时数据用数据工具、专业判断找对应专业人士、展示辩论用通用对话/专门辩论 skill
- **风险**：头号风险=内部辩论被偷懒跳过，直接吐一个普通答案——必须在流程中强制走完"理解意图→建设者方案→挑剔者找碴→多轮辩论→收敛"全程；次风险=过程意外外泄（违背核心诉求）；三=用户说得模糊时输出仍不严谨（辩论要主动补全、点明假设）；四=触发词覆盖不足导致生疏用户的口语召回失败
