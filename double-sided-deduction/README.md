# 双面推演（Double-Sided Deduction）

一个给 AI Agent 用的 **Skill**：用户随口说个想法、说得简单甚至没讲清楚，AI 在内部用两个视角辩论几次，对外只交付一个严谨全面的方案。

> 内部静默跑「建设者把方案做扎实 → 挑剔者找漏洞抬标准 → 反复几轮 → 收敛」，用户只拿到方案，**看不到辩论过程**。

这是它和普通"多角色辩论 prompt"的根本区别：辩论是内部质控工序，不是表演给用户看的节目。

## 它解决什么问题

用户提设计想法时，往往只说一两句、指向不强、逻辑也不完整。AI 照单直接输出，方案常常不严谨、有漏洞、没想周全。

这个 skill 的价值：**不依赖用户把话说得多清楚**。哪怕输入很模糊，也在内部用两个视角辩论几次，自己把缺口补上，交出一个相对严谨、全面、可执行的方案。

特点：

- **容忍模糊输入**：用户说得越简单、越没讲清楚，内部辩论越要主动把几种可能的理解都过一遍，用合理假设补全，不反复打断用户。
- **过程内化**：建设者 / 挑剔者 / 多轮辩论 / 收敛全部在内部完成，输出里没有角色标签、没有对话体辩论。
- **单向提高标准**：挑剔者从严密性、资源浪费、落地难度、最坏情况、替代方案逐维找碴，并主动抬高要求——不是走过场。
- **强制收敛**：辩论 2–3 轮，到顶必须收口；双方诉求不可兼得时给"带条件的折中判据"，绝不和稀泥。

## 怎么用

把 `SKILL.md` 安装到你的 Agent（见下方安装），然后用自然语言触发。**不需要说术语，大白话就行**——尤其适合刚开始用 AI、不知道怎么提要求的场景。

**随口说想法类（生疏用户说法）**

- 我有个想法，帮我完善一下
- 帮我把这事做成一个方案
- 我想做个 XX，你帮我出个靠谱的方案
- 帮我想周全点 / 你帮我多想想
- 我说不清楚，你帮我理一理
- 帮我参谋参谋 / 这方案有没有坑

**挑毛病 / 推演类**

- 帮我挑挑这个方案的毛病
- 压力测试一下
- 内部推演一轮 / 正反辩一下给结论
- 对抗打磨 / 双面推演

### 示例

> **你**：我想做个帮学生找自习室的小程序，你帮我弄弄。

**Skill 输出**（示意，实际内容随输入变化）：

> 方案：定位为"校园自习室实时空位查询 + 预约"， MVP 先做三件事……（结构完整的可执行方案）
>
> 关键假设：默认目标用户为在校大学生、覆盖本校周边自习室；若实际要对外开放，则需调整……
>
> 关键判据：空位数据接入方式（校方合作 vs 用户众包）决定 MVP 范围，二者不可兼得时优先众包验证需求。

注意输出里**没有**"角色一/角色二"、没有辩论对话——这正是预期行为。

## 不做什么（边界）

- ❌ 展示完整的角色辩论对话（除非显式要求附 ≤5 行推演摘要）
- ❌ 纯闲聊、没有任何要落地成方案的想法
- ❌ 必须靠实时数据或专业资质才能判断的事（法务 / 医疗 / 财务审计）

需要这些时，skill 会明确拒绝并给替代路径。

## 安装

**方式一：放到 skills 目录**

把本仓库的 `SKILL.md` 放到你的 Agent 的 skills 目录（例如 `~/.workbuddy/skills/double-sided-deduction/SKILL.md`），重启或刷新后即可按触发词调用。

**方式二：克隆本仓库**

```bash
git clone https://github.com/hui-Elna/double-sided-deduction.git double-sided-deduction
# 然后把 SKILL.md 链接/复制到你的 skills 目录
```

本 skill 是**单文件、零依赖**：没有脚本、没有外部 API、没有数据源，纯指令驱动，任何支持 SKILL.md 格式的 Agent 都能用。
